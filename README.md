# Julia Uvarova — сайт

Исходники статического сайта [julia-uvarova.ru](https://julia-uvarova.ru/). Главная страница — `index.html`; остальные страницы находятся в `books/`, `teambuilding/`, `trainings/`, а изображения и другие ресурсы — в `assets/` и папках лендингов.

## Публикация сайта на FTP/FTPS

**Требования:** Node.js 18+ и npm. Python не нужен. Для FTP используется единственный npm-пакет [`basic-ftp`](https://www.npmjs.com/package/basic-ftp), у которого нет собственных зависимостей. Встроенные средства Node.js работают с файлами и читают `.env` без пакета `dotenv`.

### Первый запуск

1. Склонируйте проект или обновите его командой `git pull origin main`.
2. В корне проекта установите FTP-клиент:

   ```bash
   npm install
   ```

3. Скопируйте образец конфигурации в локальный `.env`:

   ```bash
   cp .env.example .env
   ```

   В Windows в командной строке используйте `copy .env.example .env`.
4. Заполните в `.env` FTP-настройки своего хостинга:

   ```dotenv
   FTP_HOST=ftp.example.com
   FTP_PORT=21
   FTP_USER=my_login
   FTP_PASSWORD=my_secret_password
   FTP_REMOTE_DIR=/public_html
   FTP_USE_TLS=true
   FTP_TIMEOUT=30
   ```

   `FTP_REMOTE_DIR` — директория, где должен лежать главный `index.html` сайта. Она зависит от хостинга: например, `/public_html`, `/www`, `/httpdocs`. Сверьте путь в панели хостинга; **при загрузке файлы с теми же именами будут перезаписаны**.

   `FTP_USE_TLS=true` означает FTPS с шифрованием (рекомендуется). Для хостинга с обычным FTP без TLS укажите `false`, но учтите, что логин и пароль в этом случае передаются открыто. Протокол **SFTP (SSH, обычно порт 22) не поддерживается**. Пассивный режим передачи выбран автоматически клиентом.

### Команды

Показать, какие файлы будут загружены, **без соединения с сервером** (работает даже без `.env` и `npm install`):

```bash
npm run deploy:dry-run
```

Загрузить файлы на хостинг:

```bash
npm run deploy
```

Запустить тесты (без соединения с хостингом):

```bash
npm test
```

Скрипт создаёт недостающие директории, сохраняет структуру папок проекта и загружает файлы последовательно. **Не удаляет** старые файлы на сервере. Перед первой публикацией сделайте резервную копию работающего сайта.

### Что попадает на сервер

Загружаются только HTML и статические ресурсы сайта: CSS, JavaScript, изображения (JPEG, PNG, WebP, AVIF, SVG и др.), шрифты, PDF, аудио/видео, XML, JSON, TXT и `.htaccess`. Точный перечень расширений указан в `scripts/deploy-ftp.mjs` (`STATIC_EXTENSIONS`).

**Не загружаются:** `AGENTS.md` и `agent.md`, `README.md`, `.env`, `.env.example`, `.gitignore`, `.deployignore`, `package.json`, Python/Node-скрипты из служебных каталогов `scripts/`, тесты из `tests/`, `node_modules/`, `.git/` и любые другие скрытые/служебные файлы (кроме `.htaccess`). Файлы неизвестных форматов также пропускаются.

Дополнительные исключения задаются в `.deployignore`: одна строка — одно имя, относительный путь или маска. Например:

```gitignore
assets/drafts/
books/old.html
*.bak
```

Поддерживаются маски `*` и `?`, комментарии начинаются с `#`. Обратные правила с `!` не поддерживаются; файлы, исключённые самим скриптом, нельзя принудительно включить. После изменения правил проверяйте результат через `npm run deploy:dry-run`.

Локальный `.env` защищён **и** через `.gitignore` (не попадёт в Git), **и** через правила публикации (не попадёт на FTP). Никогда не записывайте реальные пароли в `.env.example`.

### При проблемах

- `530 Login incorrect`: проверьте FTP-логин и пароль.
- Ошибка TLS: уточните у хостинга поддержку **FTPS**, не путайте его с **SFTP**.
- `550`: проверьте права FTP-пользователя и путь `FTP_REMOTE_DIR`.
- Не видны изображения: проверьте относительные пути и регистр имён в HTML.

### Ошибка `500 This security scheme is not implemented`

При `FTP_USE_TLS=true` сервер отклоняет запрос `AUTH TLS`. Проверьте поддержку FTPS (explicit TLS) на выбранных `FTP_HOST` и `FTP_PORT`. Только если хостинг предоставляет обычный FTP, установите `FTP_USE_TLS=false` в локальном `.env`. В таком режиме **логин, пароль и файлы передаются без шифрования**. Скрипт никогда не переключается на незашифрованный FTP автоматически.

### Ошибка `Connect ECONNREFUSED Control socket`

FTP-сервер отклонил **сетевое соединение**. Убедитесь, что `FTP_HOST` — адрес FTP-сервера из панели хостинга (без `ftp://` и путей), а `FTP_PORT` — нужный порт (обычно 21 для FTP и explicit FTPS). На Windows проверьте `Test-NetConnection имя-сервера -Port 21`; на macOS/Linux — `nc -vz имя-сервера 21`. Если соединение отклоняется, проверьте, не заблокирован ли IP из-за частых попыток входа, и обратитесь в поддержку хостинга. Смена `FTP_USE_TLS` не исправляет отказ TCP-соединения. Не отправляйте в поддержку или чат свой `FTP_PASSWORD`.
