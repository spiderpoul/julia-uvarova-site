Это папка отражает структуру сайта https://julia-uvarova.ru/
Здесь описаны общие правила построения страниц сайта.

# Дизайн система

- Petrol / глубокая бирюза #087F86 или #087A82 — главный фирменный цвет. Он одновременно технологичный, взрослый, спокойный и достаточно необычный. В нём есть ощущение компетентности, но нет корпоративной скуки.
- Яркий голубой / cyan-blue #28BCEB или #249FE8 — второй технологический цвет. Он добавляет воздуха, лёгкости, оптимизма и отлично дружит с твоими голубыми пиджаками.
- Живой оранжевый #FF7043 или чуть глубже #F2643E — цвет энергии. Но использовать его дозированно: CTA, подчёркивания, маленькие графические элементы, цифры, огонёк, отдельные слова. Тогда он реально притягивает взгляд.
- Молочный фон #FFF9F3 или #FAFAF7, а не стерильно белый. Это сразу делает психологическую часть теплее и человечнее.
- Тёмный сине-серый текст #243746 вместо чёрного. Он профессиональный, но мягче чёрного.
- И можно оставить очень немного кораллово-розового #F58CA0 как третичный акцент — не как основной цвет сайта, а на отдельных иллюстрациях, реакциях, декоративных формах. Это даст твою живость, не превращая сайт в «розовый».

По характеру эта палитра считывается примерно так:
Petrol: «она взрослая, надёжная, понимает сложные вещи».
Голубой: «она своя в технологической среде».
Оранжевый: «она энергичная, заметная, не унылый психолог».
Молочный: «здесь безопасно и по-человечески».
Немного коралла: «у неё есть характер и эмоциональность».

пропорции:
60–70% молочный / белый воздух
15–20% petrol / бирюза
5–10% яркий голубой
5–7% оранжевый
до 2–3% коралловый/розовый


# Структура исходников и переиспользование

- Редактировать страницы в `src/pages/`, сохраняя структуру URL. HTML в корне и каталогах лендингов — сгенерированный результат, его нельзя править вручную.
- Общие элементы и блоки размещать в `src/components/` и подключать через `{% include имя {"параметр":"значение"} %}`. Не копировать шапки, подвалы, кнопки, карточки и контактные блоки в новые страницы.
- Каталог компонентов, классов и пример новой страницы: `docs/design-system.md`. При добавлении или изменении публичного компонента обновлять эту документацию.
- Фирменные цвета задаются в `assets/css/tokens.css` (`--ds-*`), базовые правила — в `assets/css/base.css`. Для новых услуг использовать `assets/css/service.css`, для книг серии — `assets/css/tango.css`. Индивидуальные стили существующих страниц находятся в `assets/css/pages/`; не переносить их целиком в новые страницы.
- Подключать общий компонент `site-head` с нужным `stylesheet`. Он включает стили, навигацию и единый скрипт Метрики. Сразу после `<body>` включать `metrika-noscript`. Не вставлять отдельные копии кода счётчика в страницы. Номер счётчика 114077657 хранится в `assets/yandex-metrika.js` и `src/components/metrika-noscript.html`.
- Текст и атрибуты параметризовать через `{{name}}` (экранируется). `{{{content}}}` использовать только для доверенного HTML из репозитория. Вложенные include размещать в файлах компонентов, а не внутри JSON-параметров.
- При добавлении страницы проверять ссылки и при необходимости обновлять меню в `assets/site-navigation.js`. Сохранять содержимое, SEO-метаданные, адаптивность и индивидуальный дизайн существующих страниц, если задача не требует их изменения.

# Сборка и проверка

Для сборки и тестов нужен только Node.js 18+, установка npm-зависимостей не требуется:

```sh
node scripts/build.mjs
node scripts/build.mjs --check
node --test
git diff --check
```

После изменения исходников или компонентов пересобрать HTML и включить сгенерированные страницы в коммит. Новые страницы автоматически обнаруживаются сборкой. `basic-ftp` нужен только для FTP-публикации; не добавлять зависимости ради шаблонов или сборки без необходимости.

FTP-скрипт автоматически запускает сборку. `src/`, `docs/`, тесты и служебные файлы не должны попадать на хостинг. Перед публикацией проверять список файлов через `node scripts/deploy-ftp.mjs --dry-run`. Проверка не подключается к хостингу. Не записывать пароли и содержимое `.env` в Git или вывод команд.
