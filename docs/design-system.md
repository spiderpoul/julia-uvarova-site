# Дизайн-система и сборка страниц

## Где редактировать

- `src/pages/` — исходники 12 страниц, структура совпадает с адресами сайта.
- `src/components/` — переиспользуемые HTML-компоненты.
- `assets/css/tokens.css` — фирменные цвета `--ds-petrol`, `--ds-cyan`, `--ds-orange`, `--ds-milk`, `--ds-ink`.
- `assets/css/base.css` — общий reset и плавная прокрутка.
- `assets/css/service.css` — готовая система для услуг: консультации и подготовка выступлений.
- `assets/css/tango.css` — готовая система страниц книг серии.
- `assets/css/pages/` — особенности остальных страниц (сохранены их индивидуальные сетки, типографика и адаптивность).
- `assets/js/` — сценарии конкретных страниц; `assets/site-navigation.*` — существующее общее меню.

HTML в корне и в папках лендингов — **результат сборки**. Не редактируйте его вручную. Он хранится в Git, чтобы сайт можно было разместить на обычном статическом хостинге. Повторения в этих файлах генерируются из единственного исходника.

```sh
npm run build        # пересобрать HTML, установка пакетов не нужна
npm run build:check  # проверить, что результат соответствует исходникам
npm test            # проверить шаблоны, счётчик и публикацию
npm run deploy:dry-run
```

Публикация FTP автоматически пересобирает страницы, в том числе при прямом вызове `node scripts/deploy-ftp.mjs`. `src/` и `docs/` исключены из загрузки. Адреса страниц и ресурсов сохранены. Для локального просмотра запускайте HTTP-сервер из корня проекта: ссылки `/assets/...` рассчитаны на корень домена.

## Как создать страницу услуги

Создайте `src/pages/my-service/index.html`:

```html
<!doctype html>
<html lang="ru"><head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Название услуги — Юлия Уварова</title>
<meta name="description" content="Краткое описание услуги">
{% include site-head {"stylesheet":"service"} %}
</head><body>
{% include metrika-noscript %}
{% include service-header %}
<main><div class="wrap">
<div class="kicker">Для IT-команд</div>
<h1>Название <em>услуги</em></h1>
<p class="lead">Главная польза для клиента.</p>
<div class="grid">
{% include card {"content":"<h3>Результат</h3><p>Описание результата.</p>"} %}
</div>
{% include section {"id":"process","eyebrow":"Процесс","title":"Как проходит работа","content":"<p>Описание процесса.</p>"} %}
{% include contact {"title":"Обсудим задачу?","text":"Напишите о вашей ситуации.","label":"Написать Юлии ↗"} %}
</div></main>
{% include service-footer %}
</body></html>
```

Запустите `npm run build`: появится `my-service/index.html`. Добавьте новый адрес в меню `assets/site-navigation.js`, если страница должна быть доступна из него. Для книг используйте `stylesheet: "tango"` и компоненты `tango-header`, `tango-footer`, `tango-cycle`. Остальные страницы могут подключать свои стили через `stylesheet: "pages/имя"`.

## Каталог компонентов

| Компонент | Параметры | Назначение |
| --- | --- | --- |
| `site-head` | `stylesheet` | Общие CSS, навигация и скрипт Метрики |
| `metrika-noscript` | нет | Изображение счётчика в начале body при отключённом JS |
| `service-header`, `service-footer` | нет | Шапка и подвал страницы услуги |
| `button` | `variant`, `href`, `label` | Внешняя ссылка с оформлением кнопки; безопасное открытие новой вкладки |
| `card` | `content` (HTML) | Карточка услуги |
| `section` | `id`, `eyebrow`, `title`, `content` (HTML) | Секция с надзаголовком и заголовком |
| `contact` | `title`, `text`, `label` | Контактный блок с кнопкой Telegram |
| `tango-header`, `tango-footer` | нет | Шапка и подвал книги |
| `tango-cycle` | нет | Общий каталог семи книг цикла |

Вложенные компоненты размещайте непосредственно в HTML-файле компонента (пример — `contact` использует `button`). Не вставляйте директивы include внутрь JSON-параметров: для сложных блоков создайте отдельный компонент. Параметры — JSON со строковыми значениями. Ошибка имени, отсутствие обязательного параметра или циклическое включение прерывают сборку.

`{{name}}` экранирует текст и атрибуты. `{{{content}}}` вставляет готовый HTML: используйте только для доверенной разметки из репозитория. Если меняете контакты, обновляйте общие компоненты и меню; тексты индивидуальных предложений остаются в страницах.

## Элементы и раскладки (service.css)

| Классы | Поведение |
| --- | --- |
| `.wrap` | Контейнер 1120 px с полями на узких экранах |
| `.kicker`, `h1`, `h2`, `h3`, `.lead` | Надзаголовок, заголовки и вводный текст |
| `.actions` | Ряд кнопок с переносом |
| `.btn.primary`, `.btn.secondary` | Оранжевая основная и светлая вторичная кнопки |
| `.grid`, `.card` | Две колонки карточек; одна до 720 px |
| `.section` | Отступ между секциями |
| `.split` | Две неравные колонки; одна на телефоне |
| `.note` | Голубое примечание |
| `.dark` | Бирюзовый контактный блок |

Системы `service` и `tango` подключаются отдельно: одинаковое имя класса в разных семействах может иметь разное оформление. Новые страницы услуг собирайте из `service`, не копируйте стили из других лендингов. Общие фирменные цвета меняйте в tokens.css; отдельные оттенки и композиция остаются в стилях семейства. Палитра и пропорции описаны в `AGENTS.md`.

## Яндекс.Метрика

`site-head` подключает `/assets/yandex-metrika.js` с `defer`. Единый номер счётчика — **114077657**, настройки сохранены: `ssr`, `webvisor`, `clickmap`, `ecommerce: "dataLayer"`, `referrer`, `url`, `accurateTrackBounce`, `trackLinks`. Повторное подключение не создаёт второй init; уже подключённый tag.js с этим адресом не загружается повторно.

`metrika-noscript` включается сразу после `<body>`. При смене номера обновите скрипт и этот компонент, затем пересоберите сайт. Не добавляйте исходный код счётчика вручную в страницы. На локальном просмотре счётчик тоже подключается; автоматические тесты выполняют его в изолированной среде без отправки запросов.
